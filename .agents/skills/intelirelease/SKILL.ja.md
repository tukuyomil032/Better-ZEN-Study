# Intelirelease（日本語版）

このファイルは [SKILL.md](SKILL.md) の日本語版です。実際にスキルを読み込む入口は `SKILL.md` です。

リポジトリにあるビルド手順やアップデーターの挙動を根拠にして、GitHub リリースの設定・準備を手伝います。コードや設定を読むまでは、推測と確認済みの事実を分けて扱ってください。

## 手順

### 1. ビルドとアップデーターの前提を聞く

[質問ツールの使い分け](references/question-tools.md)を確認します。ファイルを調べる前に、まずビルドの前提を聞き、そのあとアップデーターの前提を聞きます。質問は一度に一つだけにして、すでにユーザーがすでに答えたことは聞き直さないでください。

### 2. 実際のリポジトリを調べる

変更案を出す前に、バージョンを決めるファイルとミラー、ビルドコマンドとプラットフォーム別のビルド対象、リリース対象と署名済み成果物の名前、アップデーターの提供元・設定・フィード URL、既存のリリースワークフロー、`CHANGELOG` の有無を確認してください。

### 3. 事実と保留事項を分ける

確認できたこと、まだ不明なこと、食い違いを分けて説明します。不明点が一部だけなら、その部分を保留にして、独立して決められる内容は先に進めます。署名やビルド、アップデーターの情報を推測で埋めないでください。

### 4. 残った選択肢を聞く

残った選択肢を一つずつ聞きます。今のビルド・アップデーターと両立する選択肢だけを示してください。決定は `.github/release-setup.json` に記録し、トークン、秘密鍵、証明書、パスワードなどの秘密情報は保存しません。

### 5. 選ばれた範囲だけ準備する

選ばれた範囲で、ローカル設定またはプルリクエストの準備をします。GitHubの設定も依頼された場合は、変更前にブランチ設定の案を見せ、対象範囲を明確にします。セットアップの途中でリリースや成果物を公開したり、タグをpushしたり、アプリのコードや署名鍵、アップデーターの認証情報を変更したりしません。

### 6. 結果を報告する

用意したファイルと反映した決定、残っている保留事項を報告します。実際に適用して確認できていないワークフロー、設定、リリースを有効になったものとして扱わないでください。

## 必要な資料

- セットアップ時の聞き取り、リポジトリ調査、設定形式は [references/setup.md](references/setup.md) を読んでください。
- 構造化された質問ツールの使い分けは [references/question-tools.md](references/question-tools.md) を読んでください。
- ワークフローの起動条件と権限は [references/workflows.md](references/workflows.md) を読んでください。
- フィードの配置先と互換性は [references/feeds.md](references/feeds.md) を読んでください。
- リリース公開の方法と成果物の扱いは [references/publishing.md](references/publishing.md) を読んでください。
- 実装言語が決まったら、該当する資料だけを読んでください。[JavaScript](references/javascript.md)、[Python](references/python.md)、[Bash](references/bash.md)。

## 作業範囲

作業をローカルだけにするか、プルリクエストを用意するか、GitHubの設定も扱うかはユーザーに確認します。依頼された範囲を守ってください。セットアップの依頼だけでは、リリースの作成やリポジトリ設定の変更まで許可されたことにはなりません。まだ依頼されていない外部操作や取り消しにくい操作を行う前には、明示的な許可が必要です。
